## Preparation and design judgment

After reading the task-specific authority and implementation, I adopted a decision-record projection architect and Arabic print/accessibility designer persona. The source supports authoritative decisions and rich evidence, while the current HTML exposes only part of it. The task is to project those existing facts faithfully into an understandable document. Skills actually read/applied: writing-plans (bounded tasks and verifiable steps), brainstorming (compare export architectures and fix scope before coding), frontend-design-pro (hierarchy, typography, responsive/RTL and interaction), PDF (real text extraction and rendered pages), DOCX (read authoritative document through its XML paragraphs), github-flow, Sanad, al-Muhasibi and Muhasabah. Earlier session governing reads are retained; no installation or inventory repeated.

Chosen architecture: extend the existing JSON→HTML dossier projection, with one concise first printed page backed by the full analytical/evidence pack. Use the existing Chromium browser print/Save PDF path and explicit print control; the repository already uses Playwright Chromium for PDF verification. A new server-side browser/PDF runtime or alternate reporting system is unnecessary and outside this plan. Exported JSON remains locale-neutral and includes both governed narrative locales. HTML/PDF has one selected interface locale, and every simulated page repeats both policy labels.

## Reader journey and information hierarchy

The supported executive journey is Executive → existing validated Analyst link (same case and locale) → explicit Public or Ministry Simulation selection in the Analyst workspace → existing analyst dossier action. Executive displays both branches and has no inherited direct export action; S19 adds none. Once the analyst mode is explicitly selected, dossier and return links preserve exact case, mode and locale. The direct Analyst → Dossier journey remains available. A small screen-only toolbar shows the current mode, Print / Save PDF, Download JSON and a supported return-to-workspace link. Native controls, visible focus and keyboard order work without hover. Printing hides the toolbar. A visible note explains that Chrome/Chromium's Save as PDF is the export mechanism; do not imply a server download exists.

The first printed A4 page is the decision summary: canonical product name and HS revision, date/snapshot, current state and selected route or hypothesis, public conclusion alongside a separately marked simulation conclusion, the binding evidence gap, a compact demand/supply/capability/economics/policy summary, top supporting and contradictory evidence references, lead condition and kill condition. No executive summary field introduces a calculation or inference absent from the accepted engine. More-item counts link to full conditions/evidence below; every omitted detail remains in the supporting pack. Do not shorten source statements with misleading ellipses or discard conditions to fit a page. A measured overflow stops the design for a reviewed adjustment; no clipping or unreadable font reduction.

The supporting pack has a table of contents and eleven stable sections: identity and boundary; demand; supply; gap and false-positive controls; capability and route alternatives; economics and intervention; competition/policy; rule ledger; evidence/contradictions; conditions, kill conditions and next facts; authority and reproducibility. Each section has a heading, a compact explanation of its purpose, structured values and precise evidence references. All nine route rows remain in engine order. Monetary units, source periods and method versions remain visible. A print reader can resolve an evidence ID to the corresponding passport without interactive graph access.

## Projection and branch boundary

Use dossier2.0.0 as a documented additive projection contract. Preserve old top-level fields and their meaning for current API consumers; add explicit structured blocks, a full public decision, branch-tagged public/active sections and evidence-pack references. Version change is explicit because all cases gain a common structured export contract, replacing the historical split1.2/1.3 presentation versions. Existing selection references remain present only where genuinely applicable.

Public requests never load or consult a synthetic scenario. Public output has no synthetic evidence, EVSI value, scenario input, class-if-confirmed upgrade or policy warning text; legacy synthetic_disclosure remains null. In simulated mode the public conclusion comes verbatim from real_decision and remains unchanged. Active facts carry ClassD, scenario ID and both policy labels. Public producer observations and simulated effective capacity are separate rows, never a combined statement implying observed qualified capacity.

The analysis already provides public/passport/rule/decision/capacity/economics values. Stored scenario input is needed only for accepted facts not exposed there, such as target specification, upgrade schedule, plant factors and cash-flow inputs. Retrieve it through the governed repository only for simulated mode, then verify exact opportunity/scenario/version/disclosure identity before projecting a documented whitelist. Never dump the scenario, re-run decision formulas, treat class_if_confirmed as current class, or fabricate source/evidence IDs. If a required scenario context mismatches, export fails with a typed integrity response.

Availability is explicit: a computed null or NOT_CALCULABLE stays NOT_CALCULABLE; a missing unobserved input is UNAVAILABLE; an explicitly inapplicable branch is NOT_APPLICABLE; available0 stays numeric0. Show a localized reason and unit. Public nominal capacity is never substituted for effective qualified capacity, imports for target demand, internal D* for gated publication, or absent NPV for0. Source gaps such as unnamed buyers, missing sunset, absent downside result and unknown target specification remain visible.

## Bilingual visual and print system

Use the accepted navy/teal/gold/red tokens, local Noto assets and plain editorial document layout. The screen has a centered reading column, generous section spacing and modest two-column summary cards; tablet/mobile stacks dense tables into labelled rows where needed, with no horizontal body overflow. Cards are not ornamental evidence. Links/buttons retain keyboard access, heading order, accessible names and AA contrast. Synthetic disclosure is a visible policy control, not a watermark substitute.

Arabic chrome, rule names/results/effects and deterministic labels use the Arabic catalogue/structured narratives. Genuine source quotations retain original language with a source-language caption and correct lang/dir; producer names and technical tokens remain legitimate isolates. HS codes, IDs, hashes, units, currencies, dates, standards and URLs use LTR isolation without truncation. English prose cannot be hidden in a technical-token class. Use western digits and Gregorian dates as already governed.

Print uses A4, positive page margins, minimum readable body10.5pt EN/11.5pt AR and explicit line-height tokens. The first page is one physical summary page; evidence pack starts on page2. Repeated table headers and controlled section/page breaks prevent orphan headings, detached units and unreadable split rows. Long evidence IDs/URLs may wrap at safe boundaries while preserving their full characters. Print every synthetic page with both labels in a non-overlapping footer/header region; repeated policy text is not an evidence claim. Public pages carry the ordinary public-evidence context only. No print background image, CDN, external font or embedded source fetch.

Print proof checks metadata, embedded fonts, selectable text/technical IDs, complete appendix section headings, text/page bounding boxes and policy disclosure on every simulated page. PDF extraction is not visual proof; render every PDF page and inspect all first pages plus every page of representative longest/contradictory/public/zero-support Arabic and English outputs, expanding inspection if any defect appears.

Keep the existing canonical visual path count inherited from S18b (expected128). The16 dossier images may change under this reviewed design; non-dossier changes are limited to changed catalogue/authority versions and graph run-qualified IDs. Every changed image requires declared-change review; unrelated layout/content drift fails. Preserve viewport dimensions, browser/font pins, tolerances and600KiB/16MiB budgets. Full-page PDFs/rendered evidence are separate hashed delivery artifacts, not new unreviewed golden images. No decorative stock or generated raster imagery is needed for this evidence-led document.
