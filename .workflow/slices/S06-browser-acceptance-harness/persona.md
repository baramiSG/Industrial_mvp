SLICE OBJECTIVE: A Ministry operator can run one documented command that drives the existing v0.2.0 workspace in real Chromium and fails on any console error, failed network request, inaccessible control or broken keyboard/focus path, across desktop, tablet and presentation widths, including the printable dossier under print media and as a Chromium-generated PDF — while capturing reference screenshots of the v0.2.0 baseline as documentary evidence (not as a pass/fail oracle, per owner ruling R-4). The browser gate becomes a fourth required hosted CI job and part of the local gate set. KL-22 closes.

CRITICAL RISKS: a browser suite that passes because it asserts too little (no console/network hooks, no real keyboard traversal); flaky timing (fixed waits instead of state-based waits); tests that start the server on a fixed port and collide; e2e tests that break `PYTHONPATH=src pytest -q` on machines without browsers; CDN or network dependency inside the test tooling (violates NFR-004); Arabic rendering that shows replacement glyphs on the CI runner because no Arabic-capable font is installed, giving a false "renders correctly"; visual baselines established now and then deliberately invalidated by S07 (forbidden by R-4 — S06 stores reference screenshots only); large binary screenshots bloating the repository; weakening or deleting any of the 280 existing tests; UI edits beyond genuine defects revealed by the browser gate; unpinned tool versions; printing secret values or reading `.env`.

PROHIBITED SHORTCUTS: `|| true`, retries that hide failures, sleeps in place of explicit waits, skipping console/request hooks on any journey, marking axe violations as acceptable without a recorded reason, asserting PDF success from a non-empty byte count alone, disabling existing tests, changing golden expectations, any `config/*.yaml`, `data/**`, `docs/core/**` or DOCX edit, any visual-regression oracle (deferred to S07), any change to `real_decision` semantics or synthetic labelling.

REQUIRED TESTS AND PROOFS: real Chromium journeys — portfolio load in both modes; every opportunity selector path (cards, select, "Open the steel case"); mode switch preserving the selected case; dossier HTML action (popup) and JSON copy (clipboard permission granted); printable dossier under `media=print` and `page.pdf()` producing a valid PDF (`%PDF-` header, at least one page object) for both cases and both modes; keyboard traversal reaching every interactive control with a visibly distinct focus style; axe-core WCAG 2.1 AA audit with zero violations (or each violation fixed in the UI as a recorded defect); RTL checks (computed `direction: rtl`, non-empty Arabic glyph rendering with an Arabic-capable font installed on CI); viewports 1440×900, 1024×768, 1920×1080, 2560×1440 with no horizontal overflow of the main layout and all controls visible; console-error and failed-request hooks that fail the journey; reference screenshots of the principal journeys at each width stored as documentary evidence with an index; the whole suite runnable by one command locally (`make e2e` or equivalent) and in a new hosted CI job; `PYTHONPATH=src pytest -q` still 280 passed (e2e deselected by default without browsers); `make ci` extended with the browser gate; all pre-existing gates unchanged.

ACCEPTANCE STANDARD: browser job green on the PR and on `main`; every journey/gate above observed with fresh output recorded in `test_evidence.md`; each UI defect found by the gate fixed minimally with a recorded before/after; KL-22 closed and TL-07/Gate G scope statements updated in traceability; `docs/DEVELOPMENT_GUIDE.md` and `docs/OPERATOR_RUNBOOK.md` document the browser gate; new tool versions pinned and licences recorded; no governed artifact changed; zero Supervisor and zero independent-reviewer findings.
