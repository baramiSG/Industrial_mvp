## Selected architecture and alternatives

Keep `/` as the analyst page and mount `/executive` through the existing SPA fallback and a path-selected ES-module bootstrap. Render only a fixed, reviewed executive registry. The summary and executive-case APIs supply all executive calculation/claim contracts. Fetch public and simulated **selected-case** analysis responses solely for already-governed bilingual prose, nine-route detail, capacity/capability detail and complete passports missing from the compact executive response. Join by exact opportunity, snapshot, scenario and decision identity and reject mismatches. Do not calculate any new domain value in JavaScript.

This is a bounded clarification to the original design's server-projection approach: browser aggregation over every case/screening record remains prohibited. The current executive case model has no localized_narrative, full route rows, passport URL/title/period or effective-capacity fields; existing `analyze()` provides these with governed translations (`decision_engine.py`, `executive/models.py`, `case_projection.py`, `static/modules/graph/evidence.js`). Repeating that data in a new backend schema would expand and duplicate contract work. Fetching only selected-case details reuses the existing authority without a new API/schema. Raw compact English strings are never used as Arabic UI narrative.

Rejected alternatives: replace the analyst shell wholesale (unneeded scope and KL-85/UX-02 expansion); add a new SPA framework or third-party graph (existing modules already satisfy the platform); display only compact executive values (cannot demonstrate route precedence or the full evidence trail).

## Visual and information hierarchy

Use a calm editorial layout within existing tokens and fonts: a narrow ordered journey rail, a wide reading column, clear public/simulation comparison, and a persistent source drawer/region below the active step. The distinctive detail is an eight-position evidence sequence whose current step and source links remain visible; no animation is needed to imply intelligence.

1. Header: product identity, frozen date/snapshot, case selector, Arabic/English switch, return to Analyst.
2. Boundary strip: public evidence remains the real branch; simulation is hypothetical Class D. No operational claim of Ministry approval.
3. Two equal-authority conclusion panels: Public first in semantic DOM order, Ministry Simulation second. Each panel states state, route or no defensible route, confidence and source link. The simulation panel repeats **both** policy labels. Contradiction badges use text as well as color.
4. Eight-step journey: native ordered list of links/buttons, one active article, Back/Next controls. The URL contains `opportunity`, `step` and `locale`; history and reload preserve them.
5. Four discrete decision-vector summaries (market/gap, strategic/resilience, execution feasibility, evidence confidence). No composite score, implied total or ranking.
6. “What Ministry data unlocks”: public dataset counts with separate loaded-case and screening denominators/IDs; expandable affected cases and paginated/list-limited screening IDs. Class-D EVSI is a separate labeled section with its own availability and provenance.
7. Source region: exact claim status and IDs, stored supporting/contradicting passports or actual missing needs, return-to-claim focus control. Unknown references never become a first-row source.

On desktop use existing sidebar/main scale; on tablet place the journey rail as wrapped two-column control rows above the article and stack comparison if its minimum readable width is not met. At 390px stack all sections; a route table may scroll inside its labeled region but the page must not overflow. Keep meaningful content hierarchy at 1920 and 2560 widths with bounded reading width. RTL mirrors placement through logical properties without reversing semantic step order. IDs, standards, hashes and numerical values use existing isolated technical renderers.

## State and interaction contract

- Initial load: show labeled loading skeletons, `aria-busy`, no stale values or literal zero counts. Summary failure: localized error with Retry; no case panels assembled from partial data.
- Valid empty fixture: explain no available cases; disable case navigation. Real executive summary currently fails closed when no analyses are loaded, so empty UI is defensive response validation/test fixture, not a claim about frozen data.
- Unknown query case: show localized not-found explanation and explicit return to first available case; do not silently claim the wrong case was requested. Missing query defaults to configured first case. Invalid step defaults to SIGNAL with canonical URL. Invalid locale follows existing supported-locale fallback.
- Case/locale/step updates: a single executive epoch covers summary/case/detail join and source focus. Ignore any prior response after a later intent. A failed locale fetch leaves prior locale and document/URL intact. `popstate` validates then renders without adding history entries.
- Simulation unavailable: no simulated values/metadata; keep explicit unavailable panel with public decision present. Failed detail request: entire selected-case section shows error; never retain old branch data beneath a new case heading.
- Integrity FAIL: prominent alert, named checks and affected IDs; display actual count, never zero. Transport unavailable is a separate status. Browser negative fixture proves both.
- Evidence: each major metric/rule/narrative claim links to returned claim IDs; existing exact evidence rows are focusable. Contradicting IDs remain linked. UNRESOLVED links to actual needs, not invented evidence. Escape every value, allow external links only via safeExternalUrl and rel=noopener noreferrer.
- Accessibility: skip-to-content, native controls, labels/fieldset where appropriate, aria-current=step, labeled regions, live statuses, visible focus, return-focus source navigation, no focus trap, reduced-motion setting respected. Dynamic content receives focus on step navigation, not on a passive refresh.
- Analyst preservation: retain all existing analysis values, order, case/mode controls, screening, extraction, dossier and graph behavior. Add explicit Executive navigation and requested source links, updating exact keyboard expectations rather than weakening them. Computed integrity replaces only the existing literal `integer(0)` KPI.
