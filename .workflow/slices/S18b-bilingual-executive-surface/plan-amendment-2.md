## Experience decisions

### Name and source-language contract

- Define one exported `nodeNamePresentation(node, locale)` in existing graph/labels.js. It returns `{text, sourceLanguage}` with sourceLanguage either `en` or null. Keep nodeLabel as a compatibility wrapper returning text. No payload mutation.
- A name is available only when it is a nonempty string and its trimmed value is not the exact governed UNAVAILABLE sentinel. Null/undefined/empty remain absent. Do not broadly treat arbitrary words such as unknown, N/A or unavailable company-name substrings as sentinels. Preserve the original non-sentinel source string in output; do not translate or invent a replacement.
- In Arabic choose available name_ar; otherwise available original name_en with sourceLanguage=en. In English choose available name_en. If the selected branch has no available name, retain the existing localized node-kind fallback; sourceLanguage=null. This does not claim an entity name has become known.
- Both native and SVG rendering consume the same presentation helper; remove their independent truthiness decisions. Full original fallback names remain in native button text, accessible selection names and SVG title. SVG's existing governed truncation/layout remains. For each Arabic-locale English fallback, independently mark its SVG text and full title `class="source-language-island" lang="en" dir="ltr" direction="ltr"`, with a direct sibling SVG `desc.source-language-caption` holding the exact existing Arabic catalogue caption (`lang="ar" dir="rtl"`). The corresponding native caption is visibly rendered and linked by aria-describedby, as specified in the correction design. Never put a source-language class or LTR wrapper on the whole graph, SVG or node group; never reverse/transliterate names. Native/full-title names are verbatim; the decorative SVG text retains only its already-governed truncation.
- In Arabic native name content uses existing sourceIsland escaping/lang=en/dir=ltr and an adjacent **phrasing-element** `.source-language-caption` containing the exact existing `source_language.caption` catalogue value. Put both inside one `.graph-node-name` span so the existing parity helper can see the direct sibling caption. Do not put a paragraph inside a button, duplicate evidence-policy labels in the catalogue, or classify a company name as a technical code. The caption is existing governed source-language disclosure; no new name/translation claim. Native source labels carry the full name even when the decorative SVG label truncates. Give the visible caption id=`graph-name-source-${node.id}` and the native button a matching escaped aria-describedby. The SVG desc is non-rendered metadata, never a substitute for this visible caption. Append the same catalogue caption once to the existing SVG accessible description only when an Arabic-locale English fallback exists. Preserve all original view-description text. See the concrete markup and accessible-name tests in SVG-SOURCE-DISCLOSURE-DESIGN.md.
- Keep stable node IDs, order, selected state, aria-pressed, focus restoration, evidence retrieval and public/synthetic boundaries unchanged. Existing HTML escaping applies to every name/title/attribute; test malicious names in both language branches.
