# MVP Status and Expansion Backlog

## 1. Implemented in the packaged POC

- frozen methodology and ten-document core;
- integrity manifests;
- two public snapshots;
- two synthetic Ministry-grade scenarios;
- R0–R12 ledger;
- effective capacity and capability distance;
- NPV, IRR, S\*, national value, competition and EVSI;
- dual-state evidence isolation;
- Decision Dossier;
- GenUI frontend;
- AR/EN extraction golden fixture;
- tests, WSL runner and Docker.

## 2. High-value next build increments

### P1 — Public universe expansion

Add 25–50 candidates across distinct process families. Preserve the two deep golden cases and use the expanded set for screening, not premature investment conclusions.

### P2 — Automated public acquisition

- Comtrade/BACI/GASTAT snapshot jobs;
- ZATCA tariff tree;
- Ministry of Industry/MODON directories;
- producer document crawler with evidence passports.

### P3 — Real bilingual specification corpus

Add labeled Etimad and SABER documents, purchased anchor standards and sector-specific extraction metrics.

### P4 — Plant capability graph

Create plant, line, process, equipment, certification and product-spec nodes with evidence-backed edges.

### P5 — Secure Ministry pilot

Map a limited set of real fields:

- line production and utilization;
- customs invoice description;
- importer/offtaker;
- customer qualification;
- approved-deal economics.

Run in a restricted environment and compare real route changes with the simulation story.

### P6 — Calibration and outcome learning

Use historical cases only with as-of reconstruction and realized outcomes. Approval/rejection is not the success label.

## 3. Backlog acceptance rule

A feature enters the build only when it improves one of:

- decision correctness;
- evidence cost/time;
- route clarity;
- protection against unsupported intervention;
- reproducibility;
- Ministry usability.

“More dashboard” is not a valid objective.
